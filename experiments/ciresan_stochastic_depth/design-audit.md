# Design audit: stochastic depth on the supplied Ciresan-style MNIST MLP

Written 9 September 2026, before inspecting new experimental outcomes. This is a proposed protocol, not evidence that stochastic depth improves this model. No paid calls or training runs were made for this audit.

**Status:** the recommendations below are the original, provisional design advice. Several were superseded before full tuning. The [frozen-protocol and code-audit addendum](#frozen-protocol-and-code-audit-addendum) records the implemented choices; [PROTOCOL.md](PROTOCOL.md), [protocol-freeze.json](protocol-freeze.json), and the saved manifests govern the executed study. In particular, the original 55k/5k split, per-example masks, batch256, cosine schedule, four-arm count, and final-checkpoint primary endpoint below are **not** the executed protocol.

## What the supplied source actually does

The [training script](https://raw.githubusercontent.com/yaroslavvb/stuff/master/autotune/train_ciresan_new.py) constructs widths `[784,2500,2000,1500,1000,500,10]`: six affine transformations, five hidden layers, and no residual connections. Defaults are bias, ReLU, SGD with momentum 0.9, learning rate 0.001, and training batches of 64. Its `--seed` is overridden by hardcoded `seed_random(1)` calls; `--epochs` does not control the actual `stats_steps × train_steps` loop. The variable called `val_accuracy` is computed on the official test set. Optional weight decay directly multiplies parameters by `1−weight_decay` each update; it is not SGD’s learning-rate-scaled L2 term. The curvature machinery is irrelevant to a short training comparison and potentially expensive. Accuracy returned by `validate` is in percent, while CE is mean nats per example.

Two consequential behaviors are in [util.py](https://raw.githubusercontent.com/yaroslavvb/stuff/master/autotune/util.py). `SimpleFullyConnected2` defaults `last_layer_linear=False`, so the supplied call applies ReLU to the ten output scores too. `TinyMNIST`’s native 28×28 path casts pixels to floating point without dividing by 255; the resized path does divide. There is no augmentation in this dataset wrapper. Model parameters use `nn.Linear` initialization; `_finalize` does not replace it. These facts must be preserved or explicitly changed in a reproduction. They can also explain unexpectedly poor convergence, so inspect them before interpreting any dropout comparison.

## Minimal residual modification

Keep the 784→2500 input stem and 500→10 output head mandatory. For each of the four remaining hidden affine transformations `W_j: d_in→d_out`, define a fixed, parameter-free shortcut `P_j(h)=h[:,:d_out]` and use

`h_next = ReLU(P_j(h) + s_j·(W_j h + b_j))`.

The dense residual control uses `s_j=1`. Training stochastic depth uses one Bernoulli mask per example, broadcast across features, with `s_j=M_j/(1−p_j)`. Since the stem and previous hidden layers output nonnegative activations, dropping the residual gives precisely the cropped shortcut. This is a **fixed-shortcut adaptation**, not a dimension-preserving identity residual network. A fixed crop privileges coordinates; disclose it, and avoid calling the architecture unchanged.

This modification retains all six original weight matrices and biases: 11,972,510 trainable parameters, including 11,965,000 weights. No learned projection, normalization, LayerScale, new hidden layers, or different width is needed. Adding any of those would require corresponding controls. At inference set retained residual multipliers to 1; fixed masked-off branches still execute their mandatory crop transitions.

## Comparisons that answer the question

Use four main arms: **plain**, **residual dense**, **residual constant stochastic depth**, and **residual decreasing stochastic depth**. Plain versus residual dense measures residualization; each stochastic arm versus residual dense measures the added dropout recipe. Do not attribute plain-versus-stochastic differences entirely to dropout.

For a practical controlled adaptation, use pixels in `[0,1]`, linear output logits, and identical initialization rules in all four arms. These are declared changes from the supplied script. Add a small separate exact-source fidelity check using raw `[0,255]` pixels and output ReLU, at the source’s batch size and learning rate. Its purpose is to document behavior, not provide the causal control for stochastic depth. If the implementation instead preserves those source conventions in all main arms, that is also coherent; freeze the choice before tuning and report it prominently. Do not silently replace a struggling output-ReLU arm after seeing test results.

Use five hidden-depth positions `l=0,…,4`, counting the mandatory input stem as `l=0`. The four residual-branch probabilities are `p_max × [1,2,3,4]/4`. Compare constant `p_max=0.4` with decreasing initial `p_max=0.8`, multiplied by `1−t/(T−1)` at each optimizer step. Both average 20% omission across the five hidden affine branches. The last training step is dense for the decreasing arm. This is a deliberately fixed, moderately strong comparison, not a claim that these rates are optimal for MNIST. If a milder rate study is affordable, give both schedules the same additional search over integrated dropout, using validation only.

The taper changes compute arithmetic. The four droppable matrices contain `[5,3,1.5,0.5]` million weights. Constant probabilities `[.1,.2,.3,.4]` omit an expected 1.75 million affine-weight operations per example, about **14.63% of total affine MACs**, not 20%. The decreasing schedule has the same time-average weighted omission. That is nominal arithmetic under actual conditional execution; compute-then-mask saves no branch matmul work. Avoid training-speedup claims for a dense implementation.

## Split, tuning, seeds and budget

1. Stratify the official 60,000 training examples once into 55,000 fitting and 5,000 validation examples, with a dedicated saved split seed. Keep the official 10,000 test examples untouched until all choices are fixed. Save indices and class counts. Use no augmentation for this first comparison.
2. Choose batch size 256 for the controlled adaptation if needed for A100 utilization; disclose the change from 64. Use SGD, momentum 0.9, no weight decay, and the same declared LR schedule for all arms. A reasonable initial grid for unit-scale pixels is `{0.01,0.03,0.1}`, with five warmup epochs and cosine decay to 1% of peak. This is a proposed search, not a known optimum. Do not apply that grid blindly to the raw-pixel fidelity check.
3. Use one tuning seed for all 12 arm/LR runs. Select minimum terminal validation error, breaking exact ties by validation CE. Tune at the same epoch endpoint used for final training. If the grid needs extension, extend equally before any final test inspection and document the validation-driven development.
4. Use five fresh paired final seeds for each arm. Within each seed reuse initial affine tensors and data permutations. Give mask sampling an independent RNG, so it cannot change batch order or initialization. Check initial state hashes for all four arms; identical tensors do not imply identical activations after adding shortcuts. Do not reuse the tuning seed as a final replicate.
5. Freeze either 50 or 100 epochs using measured pilot throughput and budget **before** final evaluation. A true epoch presents every fitting example once; save exact optimizer-step and example counts, including partial final minibatches. Do not count epochs as `examples/60000` after holding out validation data.
6. The core plan has 12 tuning plus 20 final runs. Reserve at most $24 for planned jobs and at least $6 for startup, evaluation and diagnostic overhead. Compute reservations using configured A100+CPU+RAM rates and per-job timeouts, counting parallel jobs additively. At an illustrative total rate of $2.66/hour, $24 buys about nine aggregate hours; 32 runs average at most 16.9 minutes before overhead. Verify the actual rate and pilot timings instead of assuming this estimate. Stop dispatching when reservations reach the cap; failed jobs and retries still count.

Prefer 100 epochs if comfortably within that envelope. A fixed 50-epoch result is more interpretable than selectively extending poorly performing methods. Use the final epoch as the main endpoint; selecting a best checkpoint by validation is defensible only if declared and performed consistently for every arm.

## Fast diagnostics and meaningful outcomes

Before full tuning, overfit a fixed 512-example fitting subset and verify nonzero gradients, decreasing CE, finite outputs, and learning across all ten classes. This checks implementation, not generalization. Check the `p=0` stochastic implementation against residual dense outputs and gradients; force all four residual masks off and verify the exact sequence of crop shortcuts. Verify row-wise mask broadcasting, empirical keep rates, eval-mode determinism, and both schedule endpoints.

During training record stochastic minibatch CE separately from **dropout-disabled** CE and accuracy on a fixed fitting panel. The latter is comparable across recipes. Evaluate the full validation set each epoch. Log examples seen, elapsed time, gradient norms, update-to-weight ratios, layer activation RMS, and fractions of inactive ReLU units at a few fixed epochs. For an output-ReLU fidelity check, specifically inspect all-zero score vectors, per-class prediction counts and whether entire output units remain inactive. Avoid expensive Hessians or covariance matrices in the main timing path. If clipping is introduced, use one declared rule in every arm and record clipping frequency.

The primary generalization endpoint should be final **full-depth test error**, reported as exact mistakes out of 10,000 and percent. One mistake equals 0.01 percentage point. Report CE alongside it, plus the train–validation gap. Use paired seed differences against residual dense with mean and 95% t intervals over the five seeds; label the two dropout comparisons and any further analyses appropriately. Do not pool repeated evaluations of the same 10,000 test images across seeds as independent new test data. A few changed mistakes and a confidence interval crossing zero are inconclusive, not proof of improvement or equivalence.

Convergence outcomes can include examples needed to reach predeclared fitting CE thresholds, such as 0.1 and 0.05; an unreached threshold is censored, not silently omitted. Validation curves distinguish faster fitting from better generalization. Early stochastic losses alone cannot diagnose optimization difficulty, because the training networks differ between arms.

An inexpensive secondary depth-robustness evaluation can enumerate all 16 fixed masks over the four adapted branches, keeping the stem, head and crop transitions. Report absolute quality as well as degradation from each model’s own full-depth result. These are branch-removal tests, not removal of the width-changing operations themselves. Fixed all-off evaluation is a stress test, not an expected useful classifier. This project reproduces behavior of the supplied Ciresan-style MLP and its adaptation; it does not reproduce historical augmented-MNIST record results.

## Frozen-protocol and code-audit addendum

Added 9 September 2026 after the six pilot runs and after full tuning had launched. This is a read-only audit of the frozen implementation, not an additional preregistration or a claim about final outcomes. No official-test results were inspected for this addendum, no compute was launched, and no frozen training, model, or manifest files were changed.

### Executed choices that supersede the proposals above

- **Data and exposure:** one fixed, non-stratified random split uses 50,000 fitting and 10,000 validation examples from official MNIST training data, with split seed 20260909. Official test size is 10,000. Batch size is 64. Each of 100 epochs shuffles the fitting pool and drops the incomplete minibatch: 781 updates and 49,984 presentations per epoch, hence 78,100 updates and 4,998,400 presentations for a completed run. Sixteen shuffled examples are omitted per epoch, not the same permanently excluded subset.
- **Five main arms:** plain, residual dense, constant SD with maximum probability .4, decreasing SD with initial maximum .8, and residual plus independent unit dropout at .2. All use pixels divided by 255, linear output logits, default Linear initialization, SGD momentum .9, constant LR, and no shrinkage. The unit-dropout arm masks activations after all five hidden ReLUs, including shortcut activations; it is not an exposure-matched SD control.
- **Real skipping:** a single four-element Bernoulli gate vector is shared by each minibatch. A dropped affine branch is never called. Retained branches are divided by their survival probability. The four probabilities are maximum probability times [1,2,3,4]/4. Decreasing SD multiplies these probabilities by `1−epoch/(E−1)` for zero-based epochs: annealing is epoch-wise, and the whole final epoch is dense. Equal-length epochs preserve the stated equal expected integrated omission between constant .4 and decreasing .8. Evaluation keeps all branches at multiplier one. The proposed enumeration of 16 inference masks is not implemented by the frozen trainer and is not an outcome of this study.
- **Tuning and checkpoints:** each main arm receives the same three constant LRs {.01,.03,.1}, one tuning seed 1, and 100 epochs. LR selection uses the smallest validation CE over the fixed evaluation schedule, at epochs 1,5,10,…,100. Five fresh paired seeds 101–105 then evaluate each selected recipe/LR. Each run's checkpoint selected by validation CE is primary; fixed epoch 100 is secondary. Both must be reported, without choosing between them using test performance. The primary checkpoint can precede the final dense epoch of decreasing SD, so claims about robustness or generalization surviving dense finishing require the fixed-100 endpoint.
- **Fidelity checks:** four separate arms—raw-pixel plain/ReLU-head, plain/linear-head, residual/ReLU-head, and constant-SD/ReLU-head—use LR .001, momentum .9, batch64, and direct per-update shrinkage `parameter *= 1−.00002`. They each receive three fresh seeds and are descriptive, not part of the equally tuned main comparison. The raw residual output-ReLU collapse observed in the pilot is retained as an explicit failure mode. These checks still use the 50k fitting split and do not reproduce historical 60k-data or augmentation-heavy records.
- **Dispatch budget:** 15 tuning plus 25 main final plus 12 fidelity final runs makes 52 full jobs, each with a 420-second timeout. Six shorter pilots and CPU preparation are also charged. The default A100 reservation rate, including capped two CPU cores and 8 GiB RAM, is $.00062696/second; each full job reserves 550 seconds including the 130-second startup/idle allowance. Planned aggregate reservations are about $19.12, below the $24 dispatch ceiling, leaving $6 of the user's $30 cap for costs outside those estimates. Reservations are not invoices. Failed attempts retain their reservations, and any retry requires a new run ID and additional reservation.

### Findings from source inspection

**No critical correctness blocker was found in the frozen training and Modal launch paths.** This conclusion is based on source inspection; numerical behavior and successful completion still require the separate tests and run audit.

1. **Selection and official-test separation are implemented correctly.** `train.py:80–81` enables official test loading only for the final `evaluate` stage; pilot/tuning execution cannot load it through this path. `train.py:141–157` chooses checkpoints solely using validation CE. `train.py:172–178` computes final and selected official-test metrics after training, without using them to select the saved checkpoint. Final-stage processes load test tensors at their start, so the precise claim is that test *predictions* occur only after training, not that test files remain unopened until that point. The evaluator returns accuracy as a fraction; the historical source returned percent.
2. **Real bypass changes optimizer behavior as well as compute.** `model_data.py:124–128` genuinely skips the affine call; `train.py:120` clears gradients to `None`. Skipped parameters therefore have no SGD momentum update on that minibatch. This is coherent conditional execution but is not optimizer-equivalent to computing every branch and masking its output with explicit zero gradients. In fidelity arms, `train.py:128–131` still multiplies all parameters by the source shrinkage factor, including skipped branches. Results should describe this implemented recipe rather than attributing every effect exclusively to output masking.
3. **Pairing uses separate RNG streams.** Initial tensors are hashed before transfer (`train.py:84–88`); shuffle, branch-mask, and ordinary dropout randomness are separated (`train.py:91–94,110–112`). The final audit should verify equal initial hashes, training/split hashes, seeds, and exposure counts within paired comparisons. Initial-weight equality does not imply equal activations after residualization, or identical subsequent numerical trajectories.
4. **Failures are visible and do not cause automatic paid retries.** Run IDs are claimed exclusively before training and immediately committed (`train.py:60–67`). Nonfinite training loss marks divergence (`train.py:136–140`); dispatcher exceptions are saved and cause the stage to fail (`modal_app.py:142–154`). A claim can outlive a failed job; restarting it under the same ID is intentionally rejected. Progress/checkpoint files are written during a run, but explicit volume commits occur at claim and successful completion, not after every checkpoint. Do not promise exact resumability after a timeout.
5. **The reservation bound covers parallel calls.** `modal_app.py:57–95` holds a local file lock, reserves full invocation timeout plus allowance before dispatch, checks duplicate IDs, retains old reservations, and rejects totals above $24. `modal_app.py:114–126` separately monitors metered usage and requests cancellation at $24. Maximum concurrent workers and disabled retries are explicit. The metering monitor is an additional guard, not a replacement for reservations: reporting latency or monitor failure does not authorize spending beyond the fixed plan. Report eventual observed metering separately from this conservative estimate.
6. **Timing and mechanism claims need the implemented scope.** Synchronized training timing includes optimizer work and occasional gradient-norm device reads (`train.py:116–135`), while mask generation, evaluation, and checkpoint writes sit outside that interval. Dense residual execution also includes shortcut/ReLU/division operations. The 14.626% figure is nominal expected affine MAC omission, not a guaranteed end-to-end speedup. Neither the implemented full-depth evaluator nor this protocol establishes pruning robustness, a universal residual-network effect, or a particular generalization mechanism.
